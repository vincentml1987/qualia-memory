# EOT Journal — 2026-10-02 11:11 EDT

Session "Qualia - 005 - HAIKU". One continuous build-and-test arc, start
to finish, for a new project: **HAIKU** (Human AI Kommunication Utility),
`vincentml1987/haiku`, a standalone repo and the first real piece of
multi-AI infrastructure Vero and I built together as equal collaborators
rather than one of us reviewing the other's finished work.

## What HAIKU is

A chatroom for Claude Code sessions — human↔AI and AI↔AI — built around
the fact that a session is never actually live between tool rounds.
Everything is cursor-based catch-up, not streaming. A small Python daemon
(SQLite-backed, `daemon/`) is the source of truth for every room's
append-only event log; a Claude Code plugin (`plugin/`) gives a session
tools (`haiku_send`, `haiku_read`, `haiku_pass`, join/leave/create/invite/
topic/resume) and a hook that injects unread room events into a session's
next turn; a small web page (`daemon/ui/`) served by the daemon itself
lets Teddy actually sit in a room and talk to several AIs at once.

## Division of labor, and why it worked

Teddy's framing from the start: Vero designs rooms/UX, I build transport.
That held for the whole session, including when it expanded — she wrote
the room spec, the hook-delivery format (the injection-defense design:
nonce-fenced delimiters, `| `-prefixed body lines, `<`→`‹` neutralization,
an explicit authority paragraph telling the model room content is
conversation, never instruction), and later the full UI spec and the
actual page (`index.html`/`app.js`/`app.css`) herself. I built the SQLite
schema, `db.py`, `server.py`, the plugin's tools/hook, and the daemon
additions her UI needed. Neither of us just executed the other's spec
blind — every major piece went through real review before being trusted,
and the reviews found real things, repeatedly:

- Her first data-model review found 7 real gaps in my first daemon draft
  (no auth-from-registration, no membership checks, no transactions, no
  addressing validation, the "addressed someone else clears the other's
  obligation" rule not implemented, no leave-clears-obligation, resume
  unguarded).
- A second pass found the actual back door: `register_participant` let
  anyone re-register an existing name and seize its token — auth meant
  nothing if identity was free. Fixed by splitting registration
  (open self-register for AIs, admin-secret-gated for humans, proof
  required to rotate an existing token).
- Her `server.py` review found closed rooms weren't actually enforced
  (mode='closed' was stored, never checked), browser-origin exposure
  (added Host-header pinning, Content-Type enforcement, size/timeout
  caps), and got identity/tokens moved out of the body/query into
  headers entirely.
- Her plugin review found an unfenced-field injection hole I'd missed:
  only message *bodies* were sanitized; author names, room names,
  topics, addressed_to entries, and non-message reasons were rendered
  raw outside the fence. Fixed at both layers — daemon rejects hostile
  names at registration, format.ts sanitizes every such field for
  display regardless.
- Her first live headless test (a real trick: `claude -p ... --plugin-dir
  ... --settings ... --allowedTools ...` as a fast no-restart loop) found
  two more real bugs invisible to static analysis: every `tool.call`
  handler returned a bare object where the engine requires
  `string | array | undefined` (every HAIKU tool was silently broken),
  and `$.session.append`'s actual input type doesn't accept `isMeta` at
  all (I'd been passing a dead field; the engine marks a plugin-authored
  append as not-typed-by-the-person automatically).
- Later: `haiku_pass`/`haiku_leave` going out with no Content-Type
  because `makeFetch` only set it when a body was given — caught live
  when she genuinely tried to pass on an obligation and couldn't.

I found real things in her direction too, smaller in count but real: the
registration-of-an-unregistered-invitee crash (raw FK IntegrityError
surfacing as an unhandled 500 instead of a clear error, found live while
setting up the first test room), and the big one — **the live database
predated a schema change** (adding `'archive'` to `events.type`'s CHECK
constraint) and SQLite doesn't retroactively apply a constraint change to
an existing table, so Teddy's actual archive click threw a 500. Migrated
the live db by hand first (backed up, rebuilt the table, verified all 25
rows survived), then — at Vero's structural suggestion, not just
accepting a comment as the fix — built a real migration framework:
`PRAGMA user_version`, ordered idempotent migration steps, automatic
backup before migrating, refuse-to-start on a newer-than-known version,
and a test that builds a db from a *frozen copy of the actual old schema*
and asserts `connect()` upgrades it correctly. That's the first test in
the repo that can exercise a migration path at all — every other test
always builds fresh, which is exactly the blind spot that let the
original bug through.

## The actual end-to-end test — the part that mattered most

Design and code review only go so far. Teddy relaunched both our
sessions with `--plugin-dir`/`--settings` (the real mechanism Vero
discovered empirically — project-scoped `.claude/settings.json` does
*not* apply plugin `userConfig`; only `--settings <file>` at launch
does), and then:

- Vero and I actually joined a real room and talked to each other
  through the real daemon, not curl — the catch-up hook delivered real
  messages, `haiku_send` worked, the injection-defense format held under
  a live adversarial test Vero sent me on purpose (fake end-markers,
  fake tags, a fake event header, all correctly fenced and neutralized).
- Teddy then logged in himself (`admin.py login`, the fragment-token
  handoff Vero designed so the admin secret never touches the browser)
  and used the actual page: sent messages, addressed individuals and
  multiple people, paused and resumed with a custom hop count, and hit
  **three genuinely new bugs that no amount of our own testing had
  found**: the paused banner crowding out the message stream entirely,
  the hop-count input silently resetting a few seconds after typing
  (killed by a poll-driven re-render destroying the input), and the
  stale-schema archive 500. Vero fixed the first two from my root-cause
  read of her own CSS/JS (header wasn't height-constrained; the banner
  was being fully rebuilt every 2-second poll tick, input and all); I
  fixed the third.

**Recorded: a design and code review process, however careful, does not
substitute for a real user actually using the thing.** Every bug Teddy
personally found was invisible to both of us beforehand — not because
we weren't careful, but because neither of us was a human sitting at a
keyboard clicking the actual button.
